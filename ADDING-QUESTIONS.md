# Adding Questions — turn-the-crank guide

> How to add a question bank for **any** year (1–6) safely. The data layer is
> registry-driven + gated, so adding content is a mechanical sequence, not a
> hand-sync across files. Follow the crank and the gates catch mistakes before
> they ship.

## Architecture in one picture

```
curriculum.js            ← taxonomy: YEARS + SUBJECTS_BY_YEAR (year → subject → topic)
   │                       the single source of truth for what exists
   ▼
questions-<bank>.js       ← the Qs themselves. Each Q: { id, subject, topic, year, q, options, answer, ... }
   │
   ▼
bank-registry.generated.js  ← AUTO-GENERATED by regen:registry (scans every bank,
   │                          derives export name + year + subjects + count)
   ▼
questions.js              ← lazy dispatcher. LOADERS = BANK_REGISTRY.map(...).
   │                        loadQB() / loadQBForYear(N) — year-agnostic, works for 1–6
   ▼
q-counts.js               ← AUTO-GENERATED by regen:q-counts (per-subject + per-year counts)
                            consumed by HomeView/YearSelect/Schedule for count badges
```

Three gates keep these consistent (all run in `npm run lint:all`):
- **lint:registry** — `bank-registry.generated.js` is fresh (matches the banks on disk)
- **lint:curriculum** — every Q's `{year, subject, topic}` exists in `curriculum.js`; `q-counts` matches a live recount; every `has_questions:true` subject has ≥1 Q
- **lint:ids / lint:dupes / lint:questions / lint:academic-safety** — id uniqueness, no dup content, no answer-tells, no academic-integrity vocabulary

## The crank — adding a new bank

### 1. Make sure the subject exists in the taxonomy
Open `src/data/curriculum.js` → `SUBJECTS_BY_YEAR[<year>]`. The subject must be
there with a stable `id`. If it's a brand-new subject, add it (keep `id`
kebab-case, give it `name`, `name_en`, `icon`, `color`, `semester`). Flip
`has_questions: true` once the bank below has Qs. Add `topics: [...]` if you
want per-topic drilling (each topic needs a stable `id`).

### 2. Create the question file
`src/data/questions-<bank>.js`. Naming: `questions-<descriptive-slug>.js`
(e.g. `questions-y3-pharma.js`). Export ONE array with a `QB_`-prefixed name:

```js
// src/data/questions-y3-pharma.js
export const QB_Y3_PHARMA = [
  { id: 30001, subject: 'vet-pharm-1', topic: 'pk-basics', year: 3,
    type: 'mcq',
    q: 'คำถาม…',
    options: ['ตัวเลือก A', 'ตัวเลือก B', 'ตัวเลือก C', 'ตัวเลือก D'],
    answer: 2,                          // 0-based index of the correct option
    explain: 'คำอธิบาย…',
    source: 'ที่มา', verified: 'อ้างอิงหน้า/ข้อ' },
  // …
];
```

Rules that matter:
- **`id`** globally unique integer. Pick a fresh numeric block per bank (e.g. Y3
  pharma → 30000s) so banks never collide. `lint:ids` / `lint:dupes` enforce this.
- **`subject`** MUST equal a curriculum subject `id` (else `lint:curriculum` errors).
- **`topic`** SHOULD match a topic `id` under that subject (else a warning — fine
  for "general" Qs, but prefer declaring the topic in curriculum).
- **`year`** the curriculum year (1–6). The loader auto-tags the bank's year from
  this field — no manual year wiring anywhere.
- **`options`** no answer-tells: correct option not longest by >1.5×, no `★` / `**`
  / `…` / "ถูกทุกข้อ". Pad distractors with plausible-wrong detail. (See
  `question-writing-antipatterns` skill + `npm run lint:questions`.)
- **Cross-year / utility banks** (load for every year) → add the filename to
  `CROSS_YEAR` in `scripts/regen-bank-registry.mjs` so it's tagged `year: null`.

### 3. Turn the crank
```bash
npm run regen:registry     # re-scan banks → bank-registry.generated.js (prints year tags — eyeball them)
npm run regen:q-counts      # recompute per-subject + per-year counts
npm run lint:all            # 7 gates: ids, dupes, academic-safety, questions, registry, curriculum, validate:wiki
npm run build               # must succeed
npm run test:e2e            # cross-engine smoke 32/32 (chromium, webkit, firefox — desktop + mobile)
```
All green → commit. Any red → the message tells you exactly what's out of sync.

### 4. Commit
Stage **specific files** (never `git add -A`):
```bash
git add src/data/questions-<bank>.js \
        src/data/bank-registry.generated.js \
        src/data/q-counts.js \
        src/data/curriculum.js          # if you touched taxonomy
git commit -m "content: add <bank> (Y<n> <subject>, +<count> Qs)"
```
No `Co-Authored-By` trailer (public repo). One session = one push (Vercel quota).

## When `loadQBForYear(N)` "just works" for a new year
Nothing to wire. The dispatcher filters `LOADERS` by the bank's `year` tag
(derived from the Qs themselves) plus `year: null` cross-year banks. Add Y1–Y3
or Y6 banks the same way as Y4/Y5 — the loader, counts, and selector are all
year-agnostic.

## Service-worker note
Adding question banks is **data-only** — the entry chunk hash doesn't change, and
the per-bank data chunks are content-hashed (cache-first-then-network). **No
`SW_VERSION` bump needed.** Only bump `public/sw.js` when a deploy changes the
app shell / entry chunk (see `reference_sw-version-bump-rule`).

## Gotchas the gates catch for you
| Mistake | Caught by |
|---|---|
| `subject` not in curriculum | `lint:curriculum` (error) |
| forgot `regen:q-counts` after adding Qs | `lint:curriculum` (stale count error) |
| forgot `regen:registry` after adding a bank | `lint:registry` (stale error) |
| duplicate id across banks | `lint:ids` / `lint:dupes` |
| `has_questions:true` but bank empty | `lint:curriculum` (error) |
| answer-tell options | `lint:questions` |
| โพย-family vocabulary in source/examOrigin | `lint:academic-safety` |
