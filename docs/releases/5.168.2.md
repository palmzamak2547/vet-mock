# 5.168.2: read-aloud voices back (msedge-tts 2.1.1)

From 21 Oct every `/api/tts` call failed with an upstream 403. Read-aloud outside the
avian-medicine clips therefore fell back to the device voice. Microsoft had moved the Edge
read-aloud handshake to Sec-MS-GEC v2, and msedge-tts 2.1.1 (25 Oct) computes it. This release
is the lockfile bump (msedge-tts 2.0.7 to 2.1.1, ws 8.21.0 to 8.22.0) and its release note.

## Evidence before the change

The same probe script, run from Bangkok on 28 Oct, against each version:

| Version | Result |
|---|---|
| 2.0.7 | `Unexpected server response: 403` |
| 2.1.0 | fails |
| 2.1.1 | Thai audio, 15,408 bytes |

The 2.1.0 to 2.1.1 diff was reviewed. It changes the WSS URL and the version string, and adds a pure SHA-256 checksum module. The maintainer and the dependencies are unchanged.

## Proof

- **Pull request:** #102. Merged at 23:38 Bangkok on 28 Oct as `b173d083`.
- **CI on main for `b173d083`:** Build, Smoke e2e and VCA succeeded.
- **Vercel:** production deployment `dpl_evevYYQ3y2rEBWqdkipWt5JhpDeo` is READY for `b173d083`. The served entry chunk names 5.168.2.
- **Live, English:** `POST https://vetmock.com/api/tts` returns 200 `audio/mpeg`, 16,992 bytes, in 0.9 s.

## Limit found live

Thai still failed in production with a 502: "Stream closed before the synthesis completed (no turn.end received)". The real handler reproduced it locally, and then the library alone did too. Premwadee closes the socket on question-length Thai text after about 2.7 s, in 9 of 12 tries across three output formats. A short line passes. Niwat, Edge's other Thai voice, read the same stem 6 of 6. The fix is 5.169.3 (#106).
