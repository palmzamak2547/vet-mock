# 5.305.0: สไลด์ใต้เฉลยแสดงหน้าที่สองด้วย

## สิ่งที่นิสิตเห็น

- **ข้อที่คำตอบอยู่บนสไลด์สองหน้า แสดงหน้าที่สองพร้อมไฮไลต์ต่อใต้หน้าแรก** เช่น หัวข้ออยู่หน้าหนึ่งและรูปอยู่หน้าถัดไป
  แต่ละหน้ามีชื่อสไลด์และเลขหน้าของตัวเอง ชุดคาดการณ์ One Health ปลายภาคได้หน้าที่สอง 23 ข้อ
- หน้าสรุป One Health ปลายภาคมีภาพสไลด์ 24 หน้า จาก 22 หน้า บรรทัดที่อ้างหน้าที่เป็นหน้าที่สองของเฉลยก็ได้ภาพด้วย

## What changed

- `src/lib/evidence.js`: `evidenceFor` reads the further pages a row files after the hash (5.304.0) and returns them
  as `more`, in reading order. Each page is checked on its own and left out when it is not exactly five fields, names
  a document the file does not hold or names it by a string, has a page that is not a whole number from 1 within the
  safe integer range, has a width or height that is not a finite positive number, or has a box that is not four
  finite numbers (a list with an empty place counts as malformed). A malformed first page still shows nothing,
  whatever follows it, and an edited question still drops every page.
- `src/components/EvidenceSlot.jsx`: the card draws the first page and then each further page under it, with the same
  frame, citation line and full view, painted together.
- `src/components/AnswerEvidence.jsx`: with two pages under one answer there are two "ดูสไลด์ที่ใช้เฉลย" buttons, so
  each button is described by its own citation line (`aria-describedby`): a screen reader says which page it opens.
- `src/lib/wrap-slide.js`: `slideIndex` also reads the further pages, so a wrap-up line that cites one finds its
  picture, and it files only whole page numbers with finite sizes. The One Health final wrap-up goes from 26 lines
  that find a page to 28, and from 22 pages drawn to 24.
- `src/lib/wrap-slide.js` and `src/views/WrapUpView.jsx`: which line of an item draws which page is now worked out
  once per item (`itemSlides`) before the lists draw, in full reading mode only. A page is drawn once, under the first
  line that takes it, and a line whose first page is already drawn takes the next page it cites that has a picture,
  so filing more pages never takes a picture away from a line. The list used to mark a page as drawn while it
  rendered, so React StrictMode, which renders each list twice in development, found every page taken on the second
  pass and drew none. Production rendered once and was not affected; a development server now draws the same slides
  as a build.
- `tests/e2e/answer-evidence.spec.js`: the question it picks is one whose answer rests on one page, since its checks
  read the answer's block as a single frame; a subject that gains a second page no longer breaks it.
- `docs/ANSWER-EVIDENCE.md`: the card shows every page of a row.

## Checks

- `tests/unit/answer-evidence.test.mjs`: an answer that rests on two pages carries the second; thirteen malformed
  further pages are each left out (an unknown document, a document named by a string, a page 0, a page 2.5, a page
  of 1e21, a zero width, an infinite width, a width given as a string, a box of three numbers, a box that is not a
  list, a list of boxes with an empty place, a page with a sixth field, a page that is not a list); an empty list
  adds nothing; a malformed first page shows nothing; an edited question drops every page.
- `tests/unit/wrap-slide.test.mjs`: a page filed only as a further page has its picture; a page number or size that is
  not a plain number gets none; an item shows each page once, and a line whose first page is already drawn takes its
  next cited page with a picture.
- The unit tests that read these modules pass (150). Every row in the shipped evidence files reads as it did.
- The One Health final wrap-up on a development server draws 24 slide frames, the pages per item the citations give
  (3, 2, 5, 1, 2, 1, 3, 1, 3, 1, 2, 0). Before this change it drew none there. No item loses a page it showed before.
- Three answers that rest on two pages, walked on a development server with the real page images: each shows both
  pages with their highlights, and no console error.
