# 5.202.0: a table reads as a table

Palm, 11 Nov 2026: "พวกคำถาม โจทย์ หรือเฉลย ... เราสามารถเก็บความ polish ได้อีกเยอะ เช่นบางข้อ Epidem
ทำเป็นตารางให้อ่านง่ายได้". A 2x2 written as a sentence makes the student build the table in their head
before the question starts.

## What a student sees

- **Epidemiology, 19 questions on 6 shared passages.** The passage is a table now: the ELISA and
  feline leukaemia 2x2s, the detection-dog study, calving and mastitis, the struvite regression
  (15 rows), and the Leptospira risk factors as one small table per factor (8 of them, each under the
  factor and its test). Two of the six had been transcribed with a note such as "ตัวเลขแต่ละกลุ่มเรียงเป็น
  จำนวน positive herds, จำนวน negative herds และ prevalence (%)" in front of rows of bare numbers.
- **12 explanations in COM IV, Repro Lecture and Herd Health** already held a table in the summaries'
  pipe form. The card showed them as bars and dashes; it draws them now, on the card, in the written
  reveal, the review list, the daily question and the SR card.
- **A table wider than the screen** says so under it ("เลื่อนตารางไปด้านข้างเพื่อดูคอลัมน์ที่เหลือ") and keeps
  its first column, the row names, in view while it scrolls. The page itself never scrolls sideways.
- **A passage that holds a table** sits above the question at every width and is shown whole, with
  the Passage button to come back to it. Beside the question, in 42% of the card, a table's Thai cells
  wrapped syllable by syllable; inside the old 380 px box a long table scrolled within a box that
  scrolls. The review list shows such a passage whole as well.
- **Read aloud**, a table is said a row at a time, each value after its column's name; a dash says
  nothing and a tick or a cross says yes or no.
- **Anki export.** A card's front now carries the question's passage (it had none, so a passage
  question could not be answered from its card), and a table is a table on the card.

## How

| | |
|---|---|
| `src/lib/rich-blocks.js` | cuts a text into prose and tables with their offsets; a text with no table comes back as the same string |
| `src/components/RichBlocks.jsx` | draws them: row headers, a name for the table, a frame that scrolls, the hint and the pinned column when it is wider than its frame; the prose still goes through the renderer it always did |
| `src/components/SmartPassage.jsx` | highlights keep their offsets in the passage's text, so a table between two runs of prose shifts nothing; a selection end that falls in a table or between blocks moves to the nearest edge of prose |
| `src/lib/tts-text.js` | `stripForSpeech` says a table a row at a time |
| `src/lib/anki-export.js` | the passage on the front, tables as tables |
| `src/App.jsx` | the arrow keys scroll a focused table instead of turning the page |
| `src/components/TermLinkedRichText.jsx` | one term card open at a time across the runs of an explanation |
| `scripts/lint-question-tables.mjs` | in `lint:data`: no table in a stem, an option, a model answer or a matching question's explanation; every table row belongs to a table that parses; 2 to 6 columns |
| `docs/QUESTION-STANDARD.md` C5 | the rule for writers |

## What was checked

- **The numbers.** The passages were converted by scripts that refuse a passage whose numbers differ
  from the original's, each counted (the same multiset before and after). Nothing was added: no row
  total that the passage did not give. An independent review compared the six with the originals cell
  by cell.
- **Nothing else changed.** A text with no table renders and is spoken exactly as before. The review
  compared the speech text of 162,132 strings with main's: only the 12 explanations and the 19
  passages differ, and a unit test keeps it so. No stem and no explanation was edited, and a passage
  is not read aloud, so no recorded clip is renamed; the 12 explanations with tables are in subjects
  that have no clips by 5.192.0's record (not checked against the bucket).
- **Two independent reviews**, one on logic and data, one on what a student meets on a phone, a
  tablet and a desktop in both themes. No blocker. What they found and this release fixes: the
  five-column Leptospira table was harder than the prose it replaced on a phone (now a table per
  factor); nothing said a wide table scrolls, and the answer's column could sit off screen; the
  review list cut a passage table at 220 px; table text was under the 14 px floor; the arrow keys
  turned the page from a focused table; in Firefox a triple-click on a passage's last paragraph no
  longer marked it; two term cards could stay open at once; the lint let a row with a lost bar and
  a table without outer bars through, and would have failed a formula written between bars.
- **By eye** at 1280 px and on an iPhone 13 viewport, before and after the reviews' fixes.
- **Tests.** `tests/unit/rich-blocks.test.mjs` (9), `tests/unit/anki-export.test.mjs` (3),
  `tests/e2e/question-tables.spec.js` (3: a passage table, an explanation table, highlights around
  tables across a reload), `npm run lint:data`.

## Known limits

- A highlight or a pen stroke a student had drawn on one of the six converted passages is not
  carried over: they are stored against the passage's text, and the text changed.
- In pen mode a swipe over a wide table draws instead of scrolling it, as it does over the rest of
  the passage.
- The phrase highlight that follows a recorded voice was not built for tables; none of the texts
  with a table has a recorded clip today.

## Not in this release

- 13 Epidemiology stems carry their data in the stem itself (a 2x2 in a sentence). Moving it to a
  table changes the stem, which is read aloud and, for three of them, already recorded. They follow
  with the read-aloud taught to keep saying the numbers.
- Lists and worked steps inside explanations.
