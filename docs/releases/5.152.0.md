# Study 5.152.0: library pages linked to topics, with evidence

## What changed

- `public.library_doc_links` (migration `20261021120000_library_doc_links.sql`, applied to
  production 2026-10-21 before this release): page N of a document linked to a curriculum
  topic (`<subject>/<topic>`, the ids VetWiki uses), with the words on that page as evidence.
  A trigger refuses any row whose evidence is not on that page's stored text or whose
  document is `pii_held`. RLS follows the document.
- `public.library_related(targets)` (SECURITY INVOKER) returns each target's documents with
  the first linked page and its evidence.
- `scripts/library-links.mjs` propose/apply/selftest builds the links from topic labels.
- Topic cards (TopicSelectView) get "เอกสาร N"; VetWiki articles get "เอกสารที่เกี่ยวข้อง".
  Each item opens the reader at the linked page. App now accepts VetWiki as a reader origin
  (before, the deck handed over from an article was cleared before the reader mounted) and
  the reader's back says "กลับบทความ".

## Kept short

Palm asked whether this would clutter the pages. A topic card only gains one small
"เอกสาร N" button; the list opens on tap and shows 3 documents ("ดูอีก N ไฟล์" for the
rest), each with at most two lines of evidence. Weak matches were dropped (row above).

## Verified locally

- Dev server: COM V topic card "เอกสาร 4" lists 3 documents and "ดูอีก 1 ไฟล์" with page and evidence; the
  Rabies article lists 2. Clicking hands the deck to the reader at the linked page (the
  dev server has no /api, so the file itself loads only on production).
