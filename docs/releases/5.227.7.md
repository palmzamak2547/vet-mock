# 5.227.7: the search box is one dialog from the tap to the close

Found while the checks of 5.227.1 ran: `tests/e2e/system-polish.spec.js:68` failed on the phone project in CI,
and 2 of 12 times locally. The cause is 5.226.0's search frame: while the palette's code downloads, a frame shows the
box, then the palette takes over. Each drew a dialog of its own, so the arrival swapped one dialog element for
another. A student who taps search on a cold phone and types or tabs in that instant acted on a dialog that was
already gone (the check found its dialog while the frame was up and read it after the swap).

- `src/components/PaletteShell.jsx` (new, in the entry chunk) draws the one dialog; the frame (`PaletteFrame.jsx`)
  and the palette (`CommandPalette.jsx`) draw only what is inside it. The frame marks the dialog
  `data-palette-frame` while it is shown; the palette points its focus trap at the same element when it takes over,
  and focuses its box in that commit. A tap on the dim background closes whichever is inside, the way it closed
  before. `CommandPalette.jsx` and its loader in `App.jsx` were changed for this fix only.
- What was typed while the code loaded stays in the box (the handoff of 5.226.0, unchanged).

Guards: `tests/unit/palette-one-dialog.test.mjs` (the shell draws the dialog, the frame draws none, the palette draws
only its contents inside the shell, the app opens search inside the shell); `tests/e2e/palette-frame.spec.js` now
also checks that the dialog element is the same one before and after the palette arrives and that the focus never
leaves it, frame by frame. `system-polish.spec.js:68` is unchanged; results below.
