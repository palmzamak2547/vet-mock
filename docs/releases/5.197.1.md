# 5.197.1: a lighter topic screen, a fallback model that is not retiring, three closed advisories

A maintenance pass on 10 Nov 2026 over what was out of date or heavier than it needed to be. Four
changes are in it; only the first and the last are something a student sees.

## 1. The topic screen and the search palette no longer download the faculty directory

`src/data/instructors.js` holds every lecturer's papers and sources. The topic screen imported it to
learn which lecturer strings have a profile, and the search palette to match names, so both
downloaded all of it. Measured on the build of this branch, gzip level 9, beyond the first load:

| What a visit downloads | Before | After |
|---|---|---|
| The topic screen's lecturer data | 299.9 KB (`data-instructors`) | 24.5 KB (`instructor-index` 23.9, `instructor-lookup` 0.5) |
| Opening the search palette | 492.1 KB | 201.1 KB |
| Opening a profile | 2.6 KB (the directory was already there) | 294.5 KB, on the tap |
| First load (`perf:budget` firstLoad js) | 224,527 B | 224,680 B (+153 B: the loading-bar fallback) |

The directory is 1,188 KB of JavaScript before compression, 828 KB of it publication lists. The index
(`src/data/instructor-index.generated.js`, from `npm run regen:instructor-index`) keeps the slug, the
names and aliases a lecturer string is matched against, and the position, areas and subjects a search
row prints or matches. A profile is opened by `InstructorProfile.jsx`, which imports the directory and
looks the row up by slug.

What changed for the student: a profile's code now downloads when the name is tapped, so the tap runs
the top loading bar until it opens (`OverlayPending`), a failed download closes with the app's usual
notice instead of doing nothing, and a finger on the chip starts the download before the tap ends.

Guards: `lint:instructor-index` (in `lint:data`), `tests/unit/instructor-index.test.mjs` (the index is
the directory's rows minus the heavy fields; every curriculum lecturer string and every name resolves
to the same person through both; neither screen imports the directory), the `lecturerIndex` route in
`perf-budgets.json` (25,060 B measured, 25,900 B budget), and `tests/e2e/instructor-profile.spec.js`
(the directory is not requested until a profile opens, from a topic chip and from search; the profile
shows its papers).

## 2. The Anthropic fallback names a model that is still served

Every Anthropic route defaulted to `claude-sonnet-4-5-20250929`, typed into four files. Anthropic
retires that id on 30 Nov 2026, inside the finals (23 Nov to 4 Dec); a retired id answers 404, which
here means no fallback on the day DeepSeek is down. The id is one constant now, `ANTHROPIC_MODEL` in
`api/_lib/llm.js` (`claude-sonnet-5-5`; `AI_GRADER_MODEL` still overrides it).

The request had to change with it:

- the model refuses a non-default `temperature`, which the chat writer sent (0.3);
- it thinks by default. A 700 to 1,200 token JSON reply can spend its whole allowance thinking, and
  the streamed answer has a 10 s first-byte deadline, so these routes ask for a direct answer
  (`thinking: { type: 'between_tools' }`); the handwriting route keeps adaptive thinking;
- a decline arrives as a 200 with `stop_reason: 'refusal'`: it fails the provider in one call.

`anthropicFields()` holds what each generation accepts. The handwriting chain is unchanged except for
its last entry (`claude-opus-5`, `claude-sonnet-5`, then the shared id).

The admin page's "ระบบภายนอก" card asked only whether the key works. It asks for the model in use now
(`GET /v1/models/<id>`): a 404 reads "เลิกให้บริการรุ่น ... แล้ว" with the line to change.

**Not measured against the live API.** This environment has no Anthropic key, so the request shape
comes from Anthropic's published migration notes and is pinned by `tests/unit/anthropic-model.test.mjs`
with a stubbed `fetch`. After the deploy, open `/app/admin` → ระบบภายนอก and read the Anthropic row;
if Vercel has `AI_GRADER_MODEL` set to the old id, remove it or set it to the new one. Server-side
fallback for declines was left off: it does not retry the `bio` category, the one a veterinary
microbiology question is likeliest to meet, and the chain already moves to the next provider.

## 3. Three advisories closed without a major version

`npm audit`, before: `vite` <= 6.4.3 (high, the dev server's launch-editor on Windows),
`follow-redirects` 1.16.0 to 1.16.1 (high; in the `/api/tts` runtime through `msedge-tts` and `axios`),
`fast-uri` 3.1.8 (moderate, build chain). After, in the root app, `ai/`, `vca/` and `research/`:
0 vulnerabilities, on Vite 6.4.6, follow-redirects 1.16.3 and fast-uri 3.1.9. The root build's
first-load, Home and exam sizes were byte for byte the same on 6.4.6 as on 6.4.3.
