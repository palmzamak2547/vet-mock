# 5.214.0: per-account limits on the server, and guards on the classes of bug the hunt found

Asked for: an infrastructure strong enough that the bugs found in the whole-system hunt cannot come
back in another place, less technical debt, and the server findings of that hunt fixed.

Four lanes were built and reviewed apart and are shipped as one release. Each lane's own notes, with
its reproductions, corrections and measurements, are in `docs/releases/5.214.0/`.

## What a student notices

- The helpers that cost money to run (explain in VetWiki, the answer check, the microphone, handwriting,
  read-aloud) count against the student's own account. A class on one Wi-Fi no longer shares one
  allowance; a guest is still counted by address.
- A written answer whose question states its points is graded out of that number (6 of the 389 short
  items state 10 or 20; the others stay at 2).
- A file the device has no copy of yet (the landing video, models, JSON under `public/`) waits for a
  slow network up to 15 s before the app says it is offline; it used to give up after 4 s on a phone
  that was online.

## Decisions worth knowing

- **Video and audio are outside the library's byte budget.** The storage API ignores `Range`, so each
  seek reads the object from its first byte. A budget that counted that would cut off a student who
  seeks in a lecture after six requests; a cap on the answer made storage reads grow with the square of
  the file (a 300 MB video watched once read 5.9 GB). Media is served exactly as before this release
  and keeps the per-link request limit; "media" is decided from the signed type or the signed file
  extension, which a member cannot change.
- **A member is never counted by address.** An earlier version of the lane did both, which refused a
  hall of 150 students from the sixteenth at full use.
- **The route sweep does not gate.** It runs with `npm run test:e2e:sweep`; it joins CI after 4 Dec.

## Known limits

- A forged token still costs one database call; a local signature check is the bound that cannot
  refuse an honest member, and is not built.
- Parallel opens of a library document with no catalogued size are counted only when each stream
  ends. An aborted stream is counted on Node 22 or later.
- Library media through a store that honours `Range` (then a cap and an honest count become possible)
  is for after 4 Dec.
- Two Thai spellings that look the same on screen as the key (sara am typed as two characters, a tone
  mark typed before its vowel) are still marked wrong on typed answers; they are listed as known
  failures in the scoring test and fixed in a later release.
- Found by the new guards and not fixed here: exam results waiting to be sent are in no backup or
  export; `unordered` on two fill-in questions changes scores but is not in the revision hash; a set
  parked across a release keeps the old question text; 83 of 143 bank and note files rely on the
  bundler's default to stay a chunk of their own.
- `lint:release-number` catches a collision only after the first of two pull requests has merged.
- The scoring tests copy the app's option-shuffle mapping instead of calling it.
