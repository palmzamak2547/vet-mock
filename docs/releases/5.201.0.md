จะได้ไม่รก" and "สร้างระบบที่ใช้จิตวิทยาในทุกๆส่วน ฝังลงไปใน infrastructure ให้แข็งแกร่ง เป็นระบบ และต่อยอดได้เรื่อยๆ".
A student no longer reads rows of settings before studying. The principles, the registry and how to
add a decision are in [../DECIDE-FOR-STUDENT.md](../DECIDE-FOR-STUDENT.md).

## What a student sees

- **A topic tap opens a set that is ready.** One line says what was arranged and why
  (`จัดให้แล้ว: 10 ข้อ, ไม่จับเวลา, เฉลยทันทีรายข้อ`), the start button sits under it, and every row is
  inside `ปรับเอง`. A student who adjusts gets their own setting next time (`ตามที่คุณตั้งไว้`), with
  `กลับไปใช้ค่าที่จัดให้` beside it.
- **The review planner** is one line of today's session, what it holds and why, with the start
  under it; the rows and counts are in `ปรับเอง`.
- **First run.** When the timetable names a paper, choosing the year goes straight to Home with
  that paper (`ตามตารางสอบ`, with `เปลี่ยน`). With no paper to offer, the phase screen is as before.
- **Home** shows one practice mode first, with its reason; the others are unchanged under `โหมดอื่น`.

## Taps

| Path | Before | After |
|---|---|---|
| Returning student, subject card to first question | 3 taps, six rows to read | 3 taps, no rows |
| Same student who wants their own count | 4 taps every time | 3 taps after the first time |
| Review from the coach card or the Home card | 2 taps, five rows to read | 2 taps, no rows |
| First run, year to Home | 2 taps | 1 tap when the timetable names a paper |
| A Home mode that is not shown first | 1 tap | 2 taps the first time, then 1 |

## How

| | |
|---|---|
| `src/lib/decide.js` | the registry: `decide(id, signals, io)` returns `{ value, why, by }`; `remember`, `rememberRows`, `forget`; storage injected, every read and every validator wrapped |
| `src/lib/decisions/*.js` | one pure rule per decision: `practice.setup`, `sr.setup`, `phase.firstRun`, `home.mode` |
| `src/lib/decide-signals.js` | builds the practice signals for the topic tap and the config screen alike |
| `docs/DECIDE-FOR-STUDENT.md` | principles, registry, screen rules, how to add a decision, what is never decided silently |

## What was checked

- `tests/unit/decide.test.mjs` (a table per decision, override precedence, invalid and hostile
  stored values, a throwing store, purity), `config-ladder.test.mjs`, `front-door-return.test.mjs`.
- `tests/e2e/decide-for-student.spec.js`: the topic tap, a remembered row and its restore, Home's
  free-practice card, the exam step-down, the first run, a hand pick on the phase screen, the
  no-paper phase screen, Home's first mode and due card, the planner's line, sizes and cold count.
- Two independent reviews before the merge, one on logic and state (1 blocker, 3 major, 7 minor)
  and one on what a student meets (8 major, 6 minor). The blocker was a red build: the contrast
  sweep clicked rows that are now tucked away. The sweeps now open `โหมดอื่น` and `ปรับเอง` and fail
  if Home's toggle is missing, and the unit tests above were written against the findings.
- Performance budget: home js 87,577 B gzip against a budget of 90,300 (+1,886 B for the engine and
  Home's rule); exam js and first-load css unchanged.
- The pull request's CI ran the full e2e matrix; a Firefox shard that waited for `load` while bank
  chunks were held was fixed in the test (`waitUntil: 'domcontentloaded'`).

## What the owner may want to change

- "Near a paper" is 14 days (the exam-prep card comes first on Home, and a topic set points at the
  exam rung). The card itself still appears from 30 days.
- The first-run skip applies on every year change, not only the first visit.
- A Home mode that is not shown first takes one more tap the first time.
