# 5.227.3: offline, one online visit is enough to reopen the app, and offline reads as offline

From the online and offline audit of 15 Nov (`C:/dev/vetmock-hunt/ui/OFFLINE-20261115.md`, pictures in
`work/offline-audit/` of the primary checkout, not committed). Service worker `v230-2026-11-15`.

## Changed

- A first visit loaded its files before the worker controlled the page, so none went through it, and an offline
  reload of that visit drew a blank page (Home and every deep link, measured on main's build). When a worker first
  takes control, `app-lifecycle.js` names the app files the page already loaded, and those still downloading as
  they finish; `sw.js` `CACHE_LOADED` keeps them (mostly from the HTTP cache) and never refetches one it holds.
  The resource timing buffer is raised to 1,000 so Home's pictures cannot crowd the chunks out.
- A set finished offline could not write its answer log: `study-event-log.js` was imported only at that moment, so
  Results showed "ยังบันทึกรายละเอียดคำตอบไม่ได้" with a backup button, also after the connection came back.
  Home warms it beside the Exam, Results and Review views.
- Pictures cached before a worker release open offline: stale-while-revalidate now reads the previous runtime too,
  which activate keeps for that purpose.
- A navigation with nothing cached gets a Thai page with one button instead of the word "Offline" (Atlas: instead of
  "Atlas is not available offline yet.").
- Every answer the worker makes up offline carries `X-VMX-Offline: 1`; `src/lib/offline-answer.js` reads it (or the
  bodies older workers send). Feedback no longer says the mail system is down, outside documents show their offline
  line, Atlas says the model is not stored on this device.
- `cacheFirst` treats a cache read that throws as a miss, as `networkFirst` does.

## Design (Rule 11)

No screen gains a control. The Thai offline page: one heading, one line, one 44 px button, light and dark, no
network needed to draw it. States: offline (this page), error (a server error still reaches the page as sent).

- e2e `offline-first-visit.spec.js` (origin cut, every engine): failed on main's build (chromium-mobile). Run locally

- `atlas-offline`, `service-worker-live-update`, `connectivity-status`, `update-and-intent` passed on chromium-mobile
  and chromium-desktop on the first version.
