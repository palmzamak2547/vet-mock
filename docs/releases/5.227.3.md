# 5.227.3: multiplayer fix wave 1, the race's edges, two dead tabs, leaving a group, names from the server

From the multiplayer audit of 15 Nov 2026 (production then: 1 race room ever, never started; 1 group with no
members and no admin; 0 shared questions; 0 comments; 105 server-marked runs from 9 students on the board).

## What changed

Race (exam-flow code: two reviews before merge)
- `src/lib/race-session.js`: `RaceBuildMismatch` (`stale: true`) when the room's question revisions differ from
  this copy of the bank; a question missing from the bank is `missing: true` (first read as a slow bank chunk).
- `src/views/RaceView.jsx`: the poll stops and shows the reload notice on `stale`, or after three polls in a row
  with questions missing; `act()` routes `stale` to the same notice (`asksForReload`). A room gone before its
  start (`Room unavailable`, or a null snapshot) shows "ห้อง {code} ปิดแล้ว" with the way back; after its start it
  stays an error line. The exit dialog says the answers are kept and names the code. The last room's code is kept
  in sessionStorage (`vmx-race-last-room`) and offered back in the join box. Guests read "รอเจ้าของห้องกดเริ่ม";
  the waiting room's back button reads ปิดห้อง (host) or ออกจากห้อง (guest) and calls `leave_race`, ignoring
  failure. The subject select, count box and join box are 16 px and 44 px tall. Words in Thai throughout.
- `supabase/migrations/20261115120000_race_leave_waiting_room.sql`: `leave_race(p_code)`, not applied.

Removed
- `src/views/LeaderboardView.jsx`: the client-score tab and its line; always `scoreSource: 'server'`.
- `src/views/GroupDetailView.jsx`: the shared-questions tab; `src/lib/api.js`: `shareQuestion`,
  `readSharedQuestion`, `getSharedQuestions`, `deleteSharedQuestion`, `recordRaceResult`, `listRaceResults`.
- `supabase/migrations/20261115120200_boards_rank_server_scores_only.sql`: both board RPCs rank server-marked
  runs only; `rr_insert_own` dropped. Not applied.

Groups
- `src/views/GroupsView.jsx`: no Leave button on the list card. `src/views/GroupDetailView.jsx`: Leave at the
  foot behind a danger confirm; the last admin is told why and offered "ลบกลุ่ม" (`deleteGroup` in api.js, which
  fails in Thai when no row was deleted). Rule in `src/lib/group-membership.js`.
- `supabase/migrations/20261115120100_group_keeps_an_admin.sql`: trigger refusing the last admin's self-delete.
  Not applied.

Who is online
- `src/hooks/useStudyBuddies.js`: payload `{ subject, view, qKey, joined_at }`; presence key `b-` plus 16 hex of
  sha256 of `vet-mock-buddies:<id>` (synchronous SHA-256, checked against node's crypto); names from
  `buddy_profiles`, cached 10 minutes, asked once on a database without it; `show_online` false means no join.
- `src/components/StudyBuddiesPanel.jsx`: names only when the server gave them, otherwise "N คน".
- `src/views/AccountSettingsView.jsx`: the `show_online` checkbox.
- `supabase/migrations/20261115120300_buddy_profiles.sql`: not applied. The SQL key was compared with the
  browser's for a constant id on production (SELECT only): both `b-f04babeee35de540`.
