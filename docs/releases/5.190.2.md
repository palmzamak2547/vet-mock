# 5.190.2: a tap in the search palette answers for the text in the box

Found while shipping 5.185.0 on 2 Nov: on a slow CI runner the palette spec opened Anatomy (VCA58-68) instead of the
deck it had typed. #137 narrowed that spec's locator; the cause was in the palette itself, so a student could hit it
too.

## Bugs, causes, fixes

1. **A paste followed by a quick tap opened the previous text's row.** The palette applies the box's text to the
   list 60 ms after it is typed (`debouncedQuery`). For that window the result rows, the course card and the
   empty-state article links were still the previous text's, and a tap opened them: paste a deck's name, tap at
   once, and another deck opened. Fix (`onSettled` in `CommandPalette.jsx`): a tap compares the box's text, read
   live from the input so a tap in the same moment as the paste counts, with the text the list applied. A result
   row whose destination `rankItems` still finds for the box's text opens at once (a recent row too, matched by
   `recentKey` since it is a copy), so assistive input that taps inside the window keeps working; rows only the
   previous text drew, the course card, the study card and the nearby-article links do nothing, and the list
   catches up within the 60 ms. Enter already acted on the box's text. The list
   carries `aria-busy` while it lags.
2. **A spoken transcript with a line break** (found in review, before release). A text input drops CR and LF from
   its value, so a query that kept one never equalled the box again, and the guard above would have held the cards
   shut for that search. `rec.onresult` now turns line breaks into a space.

The review's design question, a tap on a row that is still right for the new text: honoured, not dropped (test 2
below), so the guard only ever refuses a row the box's text no longer finds.

## Not changed

- The "ถามคลังความรู้" row asks `query`, the box's text, not the list's, so it needs no guard.

## Tests

- `tests/unit/palette-stale-tap.test.mjs`, six tests: a row only the previous text drew does nothing and the new
  text's row opens; a row the new text still finds opens at once, and so does a recent row; the previous text's course card does nothing;
  text ending in a space settles, the list is not busy and the card opens (pins the raw `setDebouncedQuery(query)`:
  a trimmed debounce would hold every card shut); a transcript with CR LF reaches the box as one line. On
  origin/main 02e44a70's palette four of the six fail. Four mutants of the fix each fail exactly their own test: a
  debounce that trims, a strict guard that drops every early tap, a match by identity that drops recent rows, and
  voice that keeps line breaks.
- `tests/e2e/library-doc-open.spec.js`, "a deck pasted into the palette and tapped at once is the deck that opens":
  types Pharmacology & Toxicology (VCA58-68), pastes Aquatic medicine (VCA58-68) and taps the Pharmacology row in
  the next task. On main's palette it fails at `expect(dialog).toBeVisible()`: the stale row opened Pharmacology.
- `tests/e2e/motion-integration.spec.js`, "leaving a set opened from the timer": waits until the first question row
  shows "ketamine" before tapping (review finding: it tapped before the list had applied the text).
