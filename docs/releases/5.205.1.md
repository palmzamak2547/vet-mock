# 5.205.1: the LINE sign-in component is updated to the version that closes a security hole

`@line/liff` (LINE's sign-in SDK) moves from 2.31.0 to 2.31.1 in the study app and in VCA. No code
changed. LINE says 2.20.0 to 2.31.0 have a cross-site scripting issue and plans to restrict those
versions around 24 November 2026. The first Year-5 final paper is on 23 November and students sign
in with LINE.

## What a student sees

Nothing changes on screen. The release note says what happened: the LINE sign-in component is
updated to the version that closes a security hole.

## Facts and sources

Read on 11 Nov 2026 from https://developers.line.biz/en/docs/liff/release-notes/ and
`npm view @line/liff`:

| Fact | Source line |
|---|---|
| XSS in 2.20.0 to 2.31.0 | "A cross-site scripting (XSS) vulnerability was identified in LIFF v2.20.0 - v2.31.0." (entry for 2.32.0, 2026/11/09) |
| Fix | "Update to LIFF v2.31.1 or later immediately." (same entry) |
| Restriction date | "we plan to restrict the use of older versions of the LIFF SDK (v2.20.0 - v2.31.0) around November 24, 2026." |
| 2.31.1 | released 2026/09/30; "LIFF v2.20.0 - v2.31.0 have been deprecated" because of an issue with potential security implications |
| npm | `time`: 2.31.0 on 2026-08-31, 2.31.1 on 2026-09-30, 2.31.2 on 2026-10-07, 2.32.0 on 2026-11-09. 2.31.0 is marked deprecated ("Update to LIFF v2.31.1 immediately"); 2.31.1 is not |

Why 2.31.1: it is the version the notes name as the fix, with no functional change. 2.31.2
(7 Oct) changes how `?` in LIFF URL query values is handled, and 2.32.0 (9 Nov) changes the channel
consent screen's LINE Official Account switch; neither is needed, and the notes ask for a check of
the LIFF app after 2.31.2. Both were left out on purpose. The range in the root `package.json` is
now `^2.31.1`; the lockfile keeps 2.31.1 and a later `npm install` is the way to move on.

## What changed

| File | Change |
|---|---|
| `package.json`, `package-lock.json` | `@line/liff` `^2.29.0` to `^2.31.1`; locked 2.31.0 to 2.31.1 (and the 40 or so `@liff/*` packages it pulls in, all 2.31.1) |
| `vca/package.json`, `vca/package-lock.json` | exact pin 2.31.0 to 2.31.1 |
| `src/data/changelog/5.205.1.js` | one `fix` entry |

`ai/`, `mobile/` and `research/` do not depend on it. Only `@liff/*` and `@line/liff` entries
changed in each lockfile; other drift that `npm install` produced (an `@types/node` and
`undici-types` pair under `@line/bot-sdk`, `follow-redirects` in VCA) was undone.

## How the SDK is used

Only `init`, `isLoggedIn`, `login`, `logout` and `getIDToken`, in `src/lib/line-liff.js` and
`vca/src/online/line.js`, loaded on demand. All are in 2.31.1 unchanged; nothing depends on a
2.31.0-only behaviour. `tests/unit/vendor-chunks.test.mjs` pins the SDK's `dist/lib/index.js` path
for the chunk split, and still passes.
