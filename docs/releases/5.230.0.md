# 5.230.0: a question set prints like an exam paper

What a student notices: on the personal question page, "พิมพ์ชุดข้อสอบ" opens a small choice of three forms
(questions only, answers at the end, the answer and its reason under each question) and then the browser's print
window, where "save as PDF" is a choice. With some questions selected only those print.

What it contains:

- `src/styles-print.css`: the one print stylesheet, on its own named page (`@page paper`) so no other printed screen
  changes. Loaded by `src/lib/print-document.js` only when a document is first printed, so the first load grows by
  nothing. A4, Sarabun, black on white at 11 pt with a 1.65 line height; three text sizes (18, 11, 9 pt); margins
  18 mm sides, 20 mm top, 22 mm bottom; left aligned; one grey line at the top and one at the bottom (page margin boxes).
- `src/lib/print-document.js`: marks the kind of document on `<html>`, loads the stylesheet, waits for fonts and
  pictures, opens the print window, removes the mark on `afterprint` (or after two minutes), ignores a second call
  while one is open. Unit test `tests/unit/print-document.test.mjs`.
- `src/components/QuestionPaper.jsx`: the paper, mounted only while printing. Number hanging in the margin, stem, then
  the options in one aligned list; true or false as two options; matching as two columns; fill in and written items get
  lines to write on (1 per blank, 3 short, 8 essay). The answer key is a table of three side by side blocks, bold header,
  hairlines between rows, no vertical lines, on its own page. Nothing about origin, cohort, lecturer or account prints.
- Entry: `QuestionManagerView.jsx`, one button beside the existing ones.
- `tests/e2e/question-paper.spec.js` (Chromium only): saves each form as a PDF, reads it back with `pdfjs-dist` and
  asserts the page range, the title on page 1, no interface word, the footer and `n / N` on every page, the answer key
  and the reasons only in the forms that ask for them.

Page gate: no interface, chip or icon is carried over (the screen's buttons, selection and counters never print); one
family, three sizes; the only rules are the hairline under the key's header, between its rows and the writing lines.

Not included (next slices): the other documents (notes topic, wrap-up, wiki article, summary window, timetable), the
buttons on the exam, results, review and topic screens (those files belong to other work this week), one wording
("พิมพ์" and "บันทึกเป็น PDF") across every screen, a real PDF file for notes and sets, the paper-only address per
document, and the audit of today's print output.
