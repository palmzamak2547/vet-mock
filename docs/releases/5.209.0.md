# 5.209.0: production tells us when it is broken

On 11 Nov 2026 DeepSeek's account (the first AI provider) ran below zero and answered HTTP 402
for hours. Nothing alerted anyone, every AI request spent two failing attempts before Anthropic
answered, and an audit then found a few more quiet faults. This release fixes those seven.

## What a student sees

- The wrong-answer coach's button ("ทำไมข้อที่เลือกถึงไม่ใช่") no longer disappears without a word
  when the service is down (`off`, `error`, `timeout`): one plain line takes its place, "ตอนนี้ยังอธิบายเพิ่มไม่ได้
  ลองใหม่ภายหลัง". When the reason is "nothing to add" (the guards declined, `rate`, `budget`) it stays
  quiet as before. This is the release's only changelog entry.

Everything else is not student-facing: it is for whoever looks after VetMock, and for search engines.

## The facts behind item 2

Read on 11 Nov 2026 (no model was called):

- https://api-docs.deepseek.com/updates, entry 2026-04-24: "The two legacy API model names,
  `deepseek-chat` and `deepseek-reasoner`, will be discontinued in three months (2026-07-24)."
- Same page, entry 2026-09-10: "The previous-generation models V4 Flash and V4 Flash Vision Exp have
  been retired;" with the names "temporarily routed to V4.1 Flash".
- https://api-docs.deepseek.com/quick_start/pricing lists `deepseek-flash` and `deepseek-v4-pro`; its
  footnote says the legacy names `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` "are still
  accepted" while "the corresponding models have been retired". `deepseek-chat` is not on the page.

So the vision hop was a duplicate of the flash call, and the `deepseek-chat` hop was a dead one.

## Decisions

- **`/atlas/` and `/app/privacy` stay in the sitemap.** The brief assumed both need a sign-in.
  Measured: `/atlas/` is the script-free atlas catalogue (200, full content, no sign-in), which
  `docs/CHULA-SIGNIN.md` lists as public on purpose; `privacy` is in `GATE_PUBLIC_VIEWS` in
  `App.jsx`. Only `/app/about` is behind the wall. A new test in `og-head.test.mjs` ties every
  indexable `/app` route to the views the wall lets through. Removing the two is one line each if
  wanted.
- **noindex, not a real 404.** Vercel cannot tell a rewrite which status to send, and a 404 page
  would not boot the app on a mistyped link. The noindex shell is the smaller change.
- **Behaviour with no 402 is unchanged except item 2.** The chains differ from before only in the
  hops item 2 removes (one dead, one duplicate). Production's `LLM_MODEL` was not read (no `.env`
  access); if it is set to another id, `deepseek-flash` now stands behind it.

## Review, and what changed after it

An independent review of the pull request found no blocker and three things to fix:

| Found | Changed |
|---|---|
| With DeepSeek at 402 and Anthropic answering, health is `degraded`, the watch only warned and ended green: exactly the 11 Nov incident, unseen again | The watch reads `primary.balance` first and fails when it is `empty`, its first error line reading "DeepSeek balance is empty: production is answering from the paid fallback; top up at platform.deepseek.com". A balance that cannot be read (`unknown`) stays a warning. `AGENTS.md` and `HANDOVER.md` say who a red scheduled run reaches: the last person who edited the workflow file, if their notifications allow it, nobody else |
| About ten requests with no retry: one timeout, one sampled URL or one platform challenge turned the run red. And `curl -w ... \|\| echo 000` printed `000000` on a connection failure | Each request is retried twice, 10 s apart (`--retry 2 --retry-delay 10 --retry-all-errors`), so only a repeated failure is red; one status code per request; the job's limit is 8 minutes for the retry case |
| `isNoBalance` matched the balance words anywhere in a 4xx body, so a prompt echoed back in an error (`...user said insufficient balance on my card`) opened the breaker | It reads only the provider's own `error.message` / `error.type` from the JSON body; the 402 rule is unchanged; a test pins the echoed case |

Also confirmed for this record (environment variable names only): production sets `DEEPSEEK_API_KEY` and
`ANTHROPIC_API_KEY` and sets neither `LLM_MODEL` nor `LLM_VISION_MODEL`, so `deepseek-flash` runs and
the chains are now `deepseek-flash`, then Anthropic.

## Not checked

- **No paid call was made**: no model, no TTS. The breaker was never exercised against the real
  provider, only with `fetch` stubbed; the real 402 body was taken from DeepSeek's documented
  "Insufficient Balance" error.
- The health route and the watch were not run against production (they ship with this release).
  The first `Production watch` run after the merge is its own proof; trigger it once with
  `workflow_dispatch`.
- The breaker lives in one function instance: a cold instance tries DeepSeek once more before it
  learns. That is by design (no shared store, no new secret).
- The coach's line was tested through the component (fake-react harness), not seen in a browser.
