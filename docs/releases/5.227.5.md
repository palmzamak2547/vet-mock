# 5.227.5: a trial link for the assistant on ai.vetmock.com

A person without a Chula account can be handed a link, `https://ai.vetmock.com/?pass=<code>`, that
opens the assistant for a limited time. The wall does not move: no policy, no table in `public` or
`vca` and no part of `chula_access_state` changed. The design, what a pass opens and never opens, and
the statements that make and end one are in `docs/CHULA-SIGNIN.md`, "Trial links".

## What changed

- Database, `supabase/migrations/20261115080000_ai_guest_pass.sql`: `private.ai_guest_pass` (the
  SHA-256 of a code, an expiry, a message cap, the count, `revoked_at`) and
  `public.ai_guest_pass_use(p_code, p_count)`, a definer function that checks and counts in one
  `UPDATE`. The pre-request is re-created word for word with one more public call,
  `/rpc/ai_guest_pass_use`, because the server asks it with the public key before any sign-in.
- Server, `api/_lib/guest-pass.js`: the header `X-VetMock-Pass` is read by `/api/ai-chat` and
  `/api/ai-transcribe` only, and only on a request with no bearer token. A good pass continues as the
  guest the gate returns while the wall is off; a refused one is `401 pass_invalid`; a database that
  cannot be asked is 503. Chat counts one message per request, transcribe checks without counting.
  The two preflights allow the header; no other route does.
- Page, `ai/`: `lib/pass.js` takes the code out of the address and keeps it on the device, `lib/api.js`
  sends it on a request with no session, `lib/wall.js` opens the page where the sign-in card would
  be. The call button is not shown, and one line under the box says what the link covers.

## Design (AGENTS.md Rule 11)

The landing page of a trial visitor is the same page with one element taken away and one added. The
call pill is gone, because the call is not opened and a button that only refuses teaches nothing. One
line in the note row under the suggestions, in the same quiet style as the line above it, says what
the link covers (`ลิงก์ทดลอง: ถามตอบได้ ไม่รวมคลังเอกสารของจุฬาฯ`): the visitor reads it once before
the first question and it leaves with the landing page, so the thread stays as it is for a member.
No banner, no new colour, no new component.

| State | What the visitor sees |
|---|---|
| Loading | the same checking screen as anyone, until the switch is known; a device that already knows the wall is on opens at once |
| Empty | the landing page with the suggestions, the standing note and the trial line |
| Error | a refused code: the sign-in card with `ลิงก์ทดลองหมดอายุแล้ว เข้าสู่ระบบด้วยอีเมลจุฬาเพื่อใช้ต่อ`; a database that cannot be asked: the answer's own error line with its retry |
| Offline | the page's existing offline line; the box is disabled as for a member |

## Before the first pass works

1. Apply the migration. Before that, compare the live pre-request with the one in
   `20261101170000_chula_wall.sql` (`select pg_get_functiondef('public.chula_pre_request()'::regprocedure)`):
   the new migration replaces it, and assumes the allow-list has those four paths.
2. Make a pass with the two statements in `docs/CHULA-SIGNIN.md`. None is created by this release.

Until the migration is applied a request with a pass answers 503; members and the wall are unaffected.

## Guards

- `tests/unit/guest-pass.test.mjs`: the header parser (length, alphabet, a 20,000-character value, a
  repeated header); the database call with a stub (asked with the public key, 6 s deadline, every
  failure is 503); the real handlers: a good pass answers as a guest and no token reaches the
  database, a refused pass is 401 before any model call, a bearer token ignores the pass (member,
  non-member and revoked), a database failure is 503, the address limit applies, the call's tools and
  `/api/ai-voice` refuse, only two preflights allow the header, and the code is in no log line.
- `scripts/test-chula-wall-db.mjs` (CI Postgres): the function on the real migration: counted once
  per use up to the cap, uncounted checks, `invalid`, `expired`, `spent`, a revoked pass reads as
  unknown, only a hash can be stored, browser roles cannot read or write the table, and the
  pre-request lets the public key reach this one call and still refuses the rest.
- `ai/tests/unit/pass.test.mjs`, `ai/tests/unit/wall.test.mjs`: the code leaves the address and is
  stored, a malformed value is not, the page opens on a held code only where the sign-in card would
  be, a member is never sent as a trial visitor, a refused code shows the sign-in card.
