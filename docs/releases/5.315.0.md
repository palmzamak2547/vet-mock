# 5.315.0: ค้นหาเจอครบทุกผล และเจอคำที่ก็อปมาจาก PDF หรือ LINE

## สิ่งที่นิสิตเห็น

- **ช่องค้นหาบอกจำนวนจริงของแต่ละกลุ่ม** คำที่เจอเยอะ เช่น rabies, dog, โรค, วัคซีน เคยรวมทุกกลุ่มได้ 80 พอดีเสมอ
  และกลุ่มที่มีผลเกินนั้นกดแสดงเพิ่มไม่ถึง ตอนนี้แต่ละกลุ่มบอกจำนวนที่เจอจริงและกดแสดงเพิ่มได้จนครบ
  คำสั้นอย่าง `a` ที่เคยไม่ขึ้นข้อสอบเลย ก็ขึ้นกลุ่มข้อสอบแล้ว
- **ข้อสอบที่ขึ้นต้นเหมือนกันเป็นคนละแถว** ข้อที่ 50 ตัวอักษรแรกเหมือนกันเคยถูกนับเป็นข้อเดียว ในคลังมี 57 ข้อที่ค้นไม่เจอ
  เพราะเหตุนี้ ตอนนี้ข้อที่โจทย์ต่างกันขึ้นทุกข้อ ส่วนข้อที่โจทย์เหมือนกันทั้งข้อยังขึ้นแถวเดียว
- **คำท้ายโจทย์ยาวค้นเจอ** เดิมค้นได้แค่ 100 ตัวอักษรแรกของโจทย์ โจทย์ที่ยาวกว่านั้นมี 2,474 ข้อ ตอนนี้ค้นได้ทั้งโจทย์
- **คำที่ก็อปมาจาก PDF หรือ LINE ค้นเจอ** คำที่มีอักขระล่องหนติดมา สระอำที่ไฟล์ PDF เก็บเป็นสองตัว (นิคหิตกับสระอา)
  และเลขไทย เช่น ๒๕๖๙ ค้นเจอเหมือนพิมพ์เอง ทั้งในช่องค้นหา รายการคลังเอกสาร สรุปบทเรียน คลิป รายชื่อวิชา และรายชื่ออาจารย์
- **ค้นหลายคำในสรุปบทเรียน คลิป และรายชื่อวิชา** ขึ้นส่วนที่มีครบทุกคำ ไม่ต้องเรียงติดกันตามที่พิมพ์ เหมือนช่องค้นหาและคลังเอกสาร

## What changed

- `src/lib/search-key.js` (new): one folding rule for every list search. A key is the text in NFC, without
  zero-width characters or soft hyphens, with a sara am stored as NIKHAHIT, an optional tone mark and SARA AA written
  as the one character a keyboard types, Thai digits as 0 to 9, lower case, every run of space as one space. Tone
  marks stay. `searchTerms(query)` splits a query into folded words; `matchesAll(hay, terms)` needs every word.
- `src/components/CommandPalette.jsx`:
  - Rows are folded with `searchKey`, and so are the query's words.
  - `rankItems` returns every hit. The cut to 80 before grouping is gone, so each group's header counts its real
    hits and "แสดงเพิ่ม" reaches all of them. The scores are unchanged; the loop no longer allocates per row.
  - A question row is one per subject and whole stem (was the first 50 characters), and its haystack holds the whole
    stem (was the first 100 characters). The row still shows the first 100.
  - The highlight uses the folded first word.
- `src/lib/omni-sources.js`: library and drug rows fold the same way as the palette's own rows.
- `src/lib/library.js`: `indexDocs` folds the shelf's haystack and `filterIndexed` folds the query.
- `src/views/NotesView.jsx`, `src/views/VideoView.jsx`, `src/views/SubjectSelectView.jsx`: folded haystacks, and every
  typed word must be found in any order (was the whole query as one phrase).
- `src/views/FacultyView.jsx`, `src/lib/thai-name-fold.js`: the exact pass and the Thai name fold read folded text,
  so a name or title holding a zero-width character is found (one record in the directory has one).
- `scripts/typecheck-files.json`: `search-key.js` is type-checked.
- `tests/unit/search-key.test.mjs` (new): the folding rule, the shelf filter, and the palette over a bank of 94
  questions: a group counts all 90 hits beside another group, a query with a zero-width space, a split sara am or
  Thai digits finds what the plain word finds, two stems that share 50 characters are two rows, and a word past
  character 100 finds its question. `tests/unit/thai-name-fold.test.mjs` builds its entries as FacultyView now does.

## Not in this release

The full-text search inside PDF pages runs on the server and is unchanged. In a 5% sample of the pages (3,389), 129
store sara am as two characters against 473 that use the one character, and 13 carry zero-width characters; a typed
word with ำ does not find those pages yet. That needs a database change, planned for after the Year-5 finals.
