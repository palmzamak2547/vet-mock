# 5.155.1: read-aloud's first word sooner on a slow network

5.155.0's first word took 2.38 s on a cold page under a slow-4G profile (150 ms RTT, 1.6 Mbps).
Three waits stacked up: all of a question's clips (9 for four options) downloaded at once and
shared the link with the first one; the first clip waited for the manifest; and the first request
to tts.vetmock.com paid DNS, TCP and TLS.

- `sharedPlan` starts the stem clip's download alongside the manifest (one small 404 when the
  manifest says no).
- `playShared` downloads the first clip alone and starts the rest once it has arrived; they fetch
  while it plays.
- An exam question opens the connection to tts.vetmock.com ahead (`<link rel=preconnect>`, once
  per page; a student who used read-aloud before also gets the subject's manifest fetched ahead),
  and the read-aloud code starts loading on pointer-down instead of on click.
