# 5.239.0: nothing fails silently

On 15 Nov the owner asked that nothing fail silently. A sweep of the code, the
database, the pipeline, production's logs and the owner's automations found the failures below; this release fixes the
small and medium ones, each with a guard that fails if the swallow comes back.

## What a student notices

- A save the browser refused is said out loud: creating or deleting a notebook (`notebook.js`, `NotebookShelf.jsx`), the
  day's task list (`useStorage.js` now answers whether it kept the value; `DailyGoalCard.jsx`), an OSCE round
  (`OSCEDrill.jsx`). Before, each ended in an empty catch and the work vanished at the next reload.
- An account the sign-up trigger left without a profile (5 of 53 on 15 Nov) gets one on its next load: `useAuth.js`
  calls `ensure_profile` once when every read answered and the row is missing.
- Thai read-aloud skips iApp at once when it is out of credit (402, 16 times on 15 Nov), as it already did when it was
  not configured (503).
- The imaging case library calls only a missing table empty; any other error shows with its reason.
- VCA: a banner when the browser will not keep practice; deletes read their rows back and say ลบไม่สำเร็จ when row
  security removed nothing; a refused like is put back.

## What the owner sees

- Browser failure counts run for every visitor (no identity, log do not prompt). A message is kept only when it is one
  the JavaScript engine or the browser writes itself, reduced (quoted text, long numbers, links, paths, token-like and
  mail-like runs and non-Latin letters become a mark); any other message is recorded as a short hash of its text, never
  the text. The stack keeps only our own bundle file with line and column; the page is a screen name, never the address
  (`safeMessage`, `safeFrame` in `src/lib/client-diagnostics.js`, again in `api/client-diagnostic.js`, which refuses a
  body over 512 bytes). `reportFailure(kind, error)` in
  `src/lib/report-failure.js` (no imports) reports `save`, `sync`, `chunk` and `load` failures from any module. The
  privacy page says so.
- `/app/admin` has the card ล้มเหลวใน 24 ชั่วโมง (`src/components/AdminFailures.jsx`, `src/lib/failure-report.js`):
  failures with message and count, accounts without a profile, failed account set-ups, every scheduled workflow's last
  run with a late verdict, pg_cron jobs, and the Vercel cron named as unreadable there.
- `scheduled-red.yml` opens one issue per red scheduled run (Production watch, Dependency updates, Android app) and per
  red Build on main. The dependency merge step fails its run when a merge did not happen.
- The Android job pins emulator build 16428233 (37.2.12, the last green), keeps the emulator's crash file on failure, and
  runs weekly.

## Database steps (written, not applied)

`supabase/migrations/20261115230000_failure_record.sql`, applied by hand after a second reader. Before and after counts
and the way back are in its header; `scripts/test-failure-record-db.mjs` runs it in CI's Postgres (Annotation
PostgreSQL job). It adds `message` and `last_at` to `private.client_error_counts`, `private.account_setup_failures`
(day, step, SQLSTATE, count; no account), `public.admin_failures(p_hours)` (is_admin only), and makes
`handle_new_user` and `handle_new_user_data` count a failure while still letting the sign-up through. Until it is
applied the app works as before: the message is sent and ignored, and the admin card says the record is not installed.
