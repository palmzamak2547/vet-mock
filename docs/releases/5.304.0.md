## What changed

- `src/data/evidence/one-health.generated.js`: rebuilt from the evidence registry after the forecast set's printed
  answer key was laid beside every slide the set shows. 15 items now show the key's page (11 of them had shown a page
  whole, with no highlight), one page shown whole gained the key's three frames, and 23 items file a second page
  after the hash. The index holds 110 questions on 95 pages of 8 documents, up from 85 pages of 9: the
  reading-material copy of the risk analysis deck is no longer cited. Seven items keep their page, because there the
  shown highlight sits on the printed words that settle the item, while the key marks a handwritten note or the
  lines around them.
- The card still shows the first page of a row. The second pages are filed for the card change that draws them; a
  card that reads six fields ignores the seventh, so this index is safe for every client already in use.
- `scripts/evidence/build.mjs`: a registry row may carry `also`, its further pages in reading order with their own
  lines and boxes. The verdict signature covers them, and a row without `also` keeps the signature it had, so every
  earlier verdict holds. `index` files them as a seventh element, `tocheck` hands them to the review sheet, and
  `upload` sends their images. The page count printed by `index` now counts the pages it wrote.
- `scripts/evidence/pages.py`: the review sheet draws every page of a row under the first, each with its boxes.
- `scripts/lint-evidence.mjs`: a row is six fields, or seven ending in a non-empty list; each further page is
  document, page, width, height and boxes, names a document of the file by its index, and no page is filed twice in
  one row.
- `docs/ANSWER-EVIDENCE.md`: the row format with further pages, and the 25 Nov pass.
- The library shelves six 2569 One Health decks (AMR, risk analysis, import risk assessment, environmental health
  risks I and II, food and feed GMOs) under the titles printed on their first pages instead of their file names. The
  One Health final wrap-up cites the decks by those printed titles, and a wrap-up line finds its slide picture by an
  exact title, so none of its lines had a picture: 26 now do. Only the title column of those six library rows
  changed, and no other row holds any of the new titles. The index carries the new titles; its rows are unchanged.
- `src/data/source-docs.js`: the four entries whose pattern did not already take the printed title now also match it,
  anchored whole, so no free-text citation reaches them that way. Every One Health source entry binds to the same
  library document as before (8 of 21; without the new patterns, 4 would have lost theirs).
- `tests/unit/library-pii-release.test.mjs`: the check that a release record copies no digits of what it held now
  leaves out the file's hash. The hash is hex of a PDF saved with its own timestamp and now and then holds nine digits
  in a row by chance, which fails the test in about one run in twenty (5.3% for 16 random hex characters).

- Rebuilding the index from the registry gives the same file byte for byte, and `tocheck` lists no row to look at:
  every verdict holds for the pages it was given on.
- Each moved page, each new frame and each second page was drawn beside the key's picture and looked at.
- All 95 cited pages answer with a webp image from the image host.
- Against the wrap-up's own citations: 26 of its 69 lines that cite a page now resolve to a slide picture, up from 0.
- `npm run lint:data`: all 72 steps pass. `npm run test:unit`: 5,206 tests, the one failure being the hash case
  above, which is fixed here; the touched tests pass again (83 tests), including a new one that feeds the lint a
  further page that is empty, repeated, of the wrong length or naming no document, and one that shows a row with
  further pages still giving its first page to the card.
