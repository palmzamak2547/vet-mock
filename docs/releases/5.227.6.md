# 5.227.6: the start button and ปรับเอง stay where they are when the count lands

Since 5.227.2 the review planner and the practice config screen are drawn before the bank has counted their cards or
questions, and the count arrives a moment later. When it did, the decide block (`.vmx-decide`) grew from one line
(`กำลังนับใบที่ถึงรอบ…`, `กำลังตรวจจำนวนข้อ…`) to its counted lines and the reason under them, so the start row below
moved down. On the config screen the rows of ปรับเอง also opened when the count landed, and the start row left its place
above the toggle, so ปรับเอง moved up. A tap made in that moment reached no button. Main's e2e caught both on 15 Nov:
`tests/e2e/sr-card-content.spec.js:47` on Firefox (the planner still on screen 15 s after the tap on `เริ่ม Session →`)
and `tests/e2e/schedule-study-loop.spec.js:17` on Chromium (ปรับเอง read closed, pressed, and stayed closed).

## What changed

- `src/components/DecideLines.jsx`, used by `SRSessionView` and `ConfigView`: while the count is on its way, the
  counting words and the line the count most likely brings share one grid cell, the second with `visibility: hidden`,
  and the reason line is drawn hidden too. The block already has the counted lines' height for that width, by real
  layout. The counting words stay the visible text of `#vmx-srs-summary` and `#vmx-config-summary`.
- The review planner draws that hidden line for one card due and the year's unseen cards as new, the shape a cold visit
  almost always counts. The start button stays enabled while counting, and a tap before the bank still starts the
  session when it arrives.
- The config screen draws its line for the set's own size until the count is known, and settles whether ปรับเอง starts
  open at the first draw instead of when the count lands. Whether the app decided the set (what is remembered) is still
  read once the count is known.
- `tests/e2e/fixtures.js` `openDisclosure` reads `aria-expanded` and presses in one step, so a toggle the app opens
  between the read and the press is no longer closed by the test.

## Measured

Start button (review planner) and ปรับเอง (practice config, from a final paper on the timetable) bounding box, read with
the bank held and again after it was released and the decided line shown. Production build, `vite preview`.

| check | desktop 1280x800 before | after | phone 390x664 before | after |
|---|---|---|---|---|
| start, ตั้งไว้แล้ว with the reset button | 52 px down | 0 px | 76 px down | 0 px |
| start, จัดให้แล้ว with the app reason | 29 px down | 0 px | 53 px down | 0 px |
| ปรับเอง | 48 px up | 0 px | 44 px up | 0 px |

A press on ปรับเอง before the count landed was already kept before this change (no remount, no reset); the new check
keeps it that way.

## Guard

- `tests/e2e/sr-card-content.spec.js`: the start button holds still when the cards have been counted, both decided
  states, within 0.5 px.
- `tests/e2e/schedule-study-loop.spec.js`: ปรับเอง holds still while the practice set is counted, and keeps a press made
  before the count.

## Not covered

The hidden line is a prediction. When the count brings a different shape (no cards due at all, an empty pool, a much
shorter line), the block still changes height; the start button is disabled in the first two. On the config screen, a
set whose count shows the app did decide it after all keeps the rows as first drawn.
