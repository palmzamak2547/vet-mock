# 5.159.0: notes fit a phone, sign-in inside app browsers, a way out of an empty review page

Items 1-3 of the ranked journey list in `docs/ux/journeys.md` section 5. Each was seen on
production first (390x844 touch, 360 px for the notes reader).

- **Notes reader at 360 px.** The grid's single track was `1fr`, which is `minmax(auto, 1fr)`:
  a wide table set the column to 405 px and `.vmx-app`'s `overflow-x: clip` cut every line on
  the right. The track is `minmax(0, 1fr)` (inline style and the 880 px media query) and the
  grid's children get `min-width: 0`, so the column shrinks to the screen and the table scrolls
  inside its own box. `tests/e2e/notes-phone-width.spec.js` opens COM III's first summary at
  360 px and asserts no grid child ends past the viewport.
- **App browsers (LINE, Facebook, Instagram, Messenger, TikTok, X).** Google refuses OAuth in
  them, so `signInPlan` (src/lib/inapp.js) hides the Google button there; inside LINE the LINE
  login (LIFF, the one sign-in that works without leaving LINE) is the first button. The
  "open in browser" notice stays. `tests/unit/inapp-signin-plan.test.mjs`.
- **Review page with no cards.** A first miss is not a card yet (a question joins the queue when
  it is missed twice), so after a first set the page said 0 cards while Home offered the missed
  questions. With no cards and still-wrong answers in the history, the page says when a miss
  becomes a card and offers "ทวนข้อที่ยังตอบผิด", the same `practiceMode: 'wrong'` set Home starts.

Nothing here runs per frame (one grid track, a button order, one note with a button), so no
perf A/B was needed (journeys.md section 4).
