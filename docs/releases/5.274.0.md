# 5.274.0: written answers in a set, the essay box, the penalty line and a self-grade that did not save

Four small fixes on the screens a student meets in a written paper and on its answers page.

## What a student notices

1. **The essay box is 16 px.** It was 14 px, and iOS Safari zooms the page when a text field under
   16 px takes focus, so tapping into the box mid-set enlarged the whole card and the student had to
   pinch back out with the clock running.
2. **The word count's penalty note reads "words, −2 pts (เกิน 200)".** The note had a left margin in
   front of its comma ("words , −2 pts").
3. **The self-marked score chip reads "10 / 15, 67%".** The percentage was its own item in a flex row
   with a 6 px gap, so the comma stood apart ("/ 15 , 67%").
4. **A self-grade the browser will not keep is said.** SmartGrader saves the ticks and the prediction
   in the browser. Both writes sat in empty catches, so in a private window or a full browser the
   marking was gone the next time the question opened and nothing said so. Now one line appears under
   the grader's header: "คะแนนที่ตรวจไว้ยังไม่ได้บันทึกในเครื่อง เบราว์เซอร์นี้เก็บข้อมูลไม่ได้ (พื้นที่เต็มหรือปิดการเก็บข้อมูลไว้) ลบไฟล์ที่ไม่ใช้ในคลังเอกสาร หรือเปิดการเก็บข้อมูลของเว็บนี้ แล้วลองอีกครั้ง" (the wording the notebook shelf and the PDF notes dialog already use). It
   leaves as soon as a later save works. Each failing stretch is counted once through
   `reportFailure('save', …)`, so it shows on /app/admin. A save that works behaves as before.

Not seen by a student: after the results are saved, ResultsView removes the parked copy of the set
(`clearCompletedExam`). A browser that refused that removal left no trace. It is now counted through
`reportFailure('save', …)` too. The student is shown nothing, because there is nothing to do: App reads
a saved, submitted copy as finished work and never offers it back, and the results render the same.
A grading history (the predictions kept across questions) that cannot be read is counted once as a
read failure and is not said as a refused save, since the browser can still store data.

## Not changed

How a paper's deadline, score or stored result is computed; the sync engine; what is saved and when.

## Checks

- `tests/unit/written-answer-marking.test.mjs` drives the real `Question.jsx` and `SmartGrader.jsx`:
  the essay box's size, the penalty note's text and margin, the chip's items, a save that works (kept,
  no line, nothing counted), a refused save (the line, one count across several ticks, the line gone
  once a save works), a refused calibration entry, and a grading history that cannot be read (counted
  as a read, no save line). Seven tests, six fail on the code before this release.
- `tests/unit/results-clear-failure.test.mjs` drives the real `ResultsView.jsx`: a clear that works
  removes the copy and counts nothing; a refused one is counted and the score still renders. The second
  fails before this release.
- The `KNOWN` lists of `text-control-font-floor` and `comma-spacing` are empty.
- `tests/e2e/table-way-back-timed-exam.spec.js` (O-023): inside a running timed paper, the student picks
  an answer, hides the passage's table, scrolls past it and taps "ดูตาราง"; the table comes back in view,
  the answer is still picked, and the remaining time has gone down by no more than the time that
  passed (still running, not refilled), with the deadline the one it had.
