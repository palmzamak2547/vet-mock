# 5.227.9: the trial link also opens the live voice call

5.227.5 gave ai.vetmock.com a trial link (`?pass=<code>`) for chat and the microphone, without the live voice
call. The owner, on seeing it, asked for the call too. This release adds it under the same caps a student's call
has, counted per link. The rules are in `docs/CHULA-SIGNIN.md`, "Trial links".

## What changed

- `api/ai-voice.js`: a request with no bearer token and a well-formed `X-VetMock-Pass` is checked with
  `requirePass(pass, res, { count: false })` instead of the Chula gate, as `api/ai-transcribe.js` does. A request
  with a bearer token is handled exactly as before, whatever header rides with it. A refused code is
  `401 pass_invalid`; a database that cannot be asked is 503. The preflight allows the header.
- Who a trial call counts as: `pass:<first 16 hex of the SHA-256 of the code>` (`passKey` in
  `api/_lib/guest-pass.js`), never the address. Every cap of the route applies to that key as it applies to a
  student: the day's sessions, the burst limit, the free restarts, the retry ticket, the photo pass and the
  photos a call; the provider balance floor applies to every start. Everyone sharing one link shares one allowance.
  The limiter still fails closed.
- `api/ai-chat.js`: the call's tools (`body.voice`) answer a trial visitor as a guest. No token, so the Chula
  library is not read. Each tool call uses one of the link's messages (the pass is counted before the body is
  read); the tools' own hourly counter is keyed by the same `pass:` key.
- The page: a trial visitor sees the call button and its hint handlers. Every request of a call already went
  through `authorized` in `ai/src/lib/api.js`, so it carries the code; a `pass_invalid` during or before a call
  drops the code, ends the call and shows the sign-in card with the trial-ended line. The note under the box reads
  `ลิงก์ทดลอง: ถามตอบและคุยด้วยเสียงได้ ไม่รวมคลังเอกสารของจุฬาฯ`.

## What a pass still never opens

The Chula library (no token on any request, the database refuses the public key), any account data, and every
other `/api` function. A photo pass from one link's call does not open another link's call.

## Read as an attacker

- A guessed code: refused by the database before anything is read or started (401), as for chat.
- A replayed or shared code: one allowance for the link, whatever addresses it comes from.
- One link starting many calls at once: the burst limit and the day's sessions are per link; the provider's
  concurrency and the balance floor bound everything.
- A member's token with a pass: the pass is ignored and the gate judges the token.
- A pass on the photo action of someone else's call: the photo pass is signed for the link's key and that
  conversation, so another link or a member gets 403.
- Logs: the code is never logged; no log line carries the `pass:` key.
