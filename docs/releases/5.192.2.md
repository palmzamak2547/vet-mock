# 5.192.2: exam results save at every score, and an exam paper gets its full time

## What shipped

1. **Some scores never reached the account, and blocked every result after them.** The server stored
   `pct = Math.round(correct / total * 100)`. In floating point that lands just under a half for 10 score pairs up
   to 300 questions (23 of 40 is `57.49999999999999`), while `exam_results_score_shape_check` (migration
   `20260824174014`, `NOT VALID`, so every new row is checked) requires `pct = round(correct * 100.0 / total)`.
   `record_exam_receipt` stored the given pct, the check refused it, `/api/exam-result` answered 503, and the outbox
   retried that first record forever with every later result on the device behind it. Pairs up to 300: 23/40, 46/80,
   69/120, 92/160, 138/240, 161/280, and 29, 57, 113 and 115 of 200.
   - `api/_lib/exam-scoring.js` rounds `correct * 100 / total` (an exact integer divided once). Results already stuck in
     an outbox go through on their next retry, since the server rescores the stored submission.
   - `src/lib/api.js`: a result an older build queued without `question_ids` is inserted directly with its own pct;
     that path now derives pct the same way. App computes the same pct, so the results page and the leaderboard agree.
2. **The exam rung got half its time.** `startNewSession` added up the whole-paper budget with the `timePerQ` of the
   previous render, while App stores the launcher's time as the setting in the same handler: the results page's
   exam rung (`timePerQ: 60`) gave 50 questions 25:00 under a 30-second setting. App now passes the time it started
   with (`timePerQ: baseTime`); a resumed whole-paper set without a deadline uses the time saved with it.

Tests seen failing first, then passing: `exam-scoring.test.mjs` (all 45,450 pairs up to 300 against
`floor((200c + t) / 2t)`), `data-api-seams.test.mjs` (the direct insert), `exam-clock.test.mjs` (25:00 before, 50:00
after, in the real hook), `exam-flow-order.test.mjs` (the lifted `startExam` passes `timePerQ`).
