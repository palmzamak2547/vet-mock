# แนวทางทำให้ข้อมูลใน VetMock เชื่อมโยงกันโดยสมบูรณ์

> เขียน 2026-09-22 หลังรอบ ingest Equine Med + Equine Repro
> ยังไม่ได้ลงมือ — เอกสารนี้คือลิสต์แนวทางกับลำดับที่ควรทำ
> **ห้ามเริ่มข้อไหนก่อนสอบกลางภาคเสร็จ** ทุกข้อแตะ data layer ที่นิสิตกำลังใช้อ่านอยู่

## ข้อสังเกตตั้งต้น — รากเดียวกันทั้งหมด

บั๊กที่เจอในคืนเดียวกันนี้ ไม่ได้มาจากหลายสาเหตุ มันมาจากสาเหตุเดียว คือ
**ข้อมูลที่ควรเป็น reference ไปหาของจริง กลับถูกเก็บเป็นข้อความอิสระ แล้วไม่มีใครตรวจว่ามันชี้ไปที่ของจริงหรือเปล่า**

หลักฐานจากรอบนี้:

| อาการ | รากของปัญหา |
|---|---|
| `verified: "FBNU52oH1z8 [12:06]"` ชี้ไปนาทีที่ไม่มีอยู่จริง | timestamp เป็น string ไม่เคยถูก validate |
| อายุรศาสตร์ม้านับข้อสอบเก่าได้ 15 ทั้งที่มี 119 | provenance อยู่ในข้อความอิสระ ไม่ใช่ field ที่มีความหมาย |
| สัตว์ปีกนับข้อสอบเก่าเกินจริง 66 แทนที่จะเป็น 50 | regex จับชื่อไฟล์ `Mid 86` ซึ่งกำกวมข้ามชั้นปี |
| `"หน้า 10"` ชี้ผิดหน้า | ไม่มี edition ผูกกับเลขหน้า ไฟล์เดียวกันมี 20 / 44 / 45 หน้า |
| 55 ข้อหายไปจาก Panic Mode | marker อยู่ 3 field และมี 2 สะกด (`อิงแนวสอบ` / `อิงแนวข้อสอบ`) |
| รูปประกอบเฉลยคำตอบตัวเอง | ไม่มีใครตรวจว่ารูปที่ crop มา มีคำตอบติดมาด้วยไหม |

ถ้าจะ polish ขั้นสุด **ต้องแก้รากนี้ก่อน ไม่ใช่เริ่มที่ UI**

## A. ทำ citation ให้เป็นของจริงที่ตรวจได้ (คุ้มที่สุด)

- **A1 — citation เป็น structured ไม่ใช่ string**
  `{kind:'video', id, at}` / `{kind:'doc', slug, edition, page}` / `{kind:'paper', cohort, part, item}`
  แล้ว render ผ่าน `humanSource()` เหมือนเดิม **UI ไม่ต้องเปลี่ยน** เพราะ layer แปลงมีอยู่แล้ว
- **A2 — lint ถาวรสำหรับความสมบูรณ์ของ citation** ⭐ เริ่มที่นี่
  ทุก timestamp ต้องมีจริงในคลิปนั้น · ทุก doc slug มีจริง · ทุกเลขหน้าอยู่ในช่วงหน้าของ edition นั้น · ทุก `image` มีไฟล์จริงใน `public/figures/questions/`
  ของมีอยู่แล้วครึ่งหนึ่ง: `work/exam-content-pipeline/scripts/audit-question-ts.mjs`
  **ข้อควรระวัง** สรุปคลิปมี timestamp เฉพาะที่หัวข้อ การอ้างนาทีกลางหัวข้อจึง "หาไม่เจอ" โดยไม่ได้ผิด — ต้องมี tolerance ไม่ใช่ exact match (`examFormat` 13 จาก 214 ดูเหมือนผิดด้วยวิธี exact match แต่ไม่ได้ผิดจริง)
- **A3 — edition-aware page citation**
  เอกสารรุ่นพี่ถูกอัปเดตเรื่อย ๆ และฉบับใหม่ **แทรกหน้า** ได้ ทำให้เลขหน้าเลื่อนทั้งชุด
  (รอบนี้ ฉบับ 45 หน้า ซ้ำหน้า 10 ไว้ที่หน้า 20 → หน้า 20-26 กลายเป็น 21-27)

## B. provenance เป็น enum ไม่ใช่ข้อความ

- **B1** `sourceType` / `examOrigin` เป็น controlled vocabulary + validate ตอน ingest
  ตอนนี้ predicate ต้องเดาจาก regex บนภาษาคน ซึ่ง**พังมาแล้ว 3 รอบ** ทั้งขาดและเกิน
- **B2** marker "เขียนจากสรุปรุ่นพี่" ให้อยู่ field เดียว สะกดเดียว
  ตอนนี้อยู่ใน `tags` / `verified` / `examOrigin` และมี 2 สะกด
- **B3** schema validation (zod หรือ JSON Schema) ของ question object ทั้งก้อน แทนการไล่เช็คทีละ lint
- **B4** duplicate detection แบบ semantic (bigram Dice) แทน prefix 48 ตัวอักษร
  เขียนไว้แล้ว: `work/exam-content-pipeline/scripts/cross-group-dupes.mjs`
  รอบนี้เจอตัวที่ prefix จับไม่ได้ 1 ข้อ

## C. ความเชื่อมโยงที่ยังไม่มี

- **C1 — graph สองทาง** question ↔ wiki section ↔ glossary term ↔ นาทีในคลิป ↔ หน้า deck
  มี `citation-index` แล้วบางส่วน แต่ยังไม่ครบวง
- **C2** จากเฉลยกดไปอ่าน wiki หัวข้อนั้นได้ / จาก wiki เห็นว่ามีข้อสอบกี่ข้อทดสอบเรื่องนี้
- **C3 — conflict ledger เป็น data ไม่ใช่ prose** ⭐ ของจริงมีเยอะกว่าที่คิด
  รอบนี้เจอ 4 จุดที่เอกสารรุ่นพี่ขัดกับคลิป และไม่ได้ถูกทำเป็นข้อสอบ:
  ฤดูผสมพันธุ์ที่ผู้เขียนขัดกับหน้าถัดไปของตัวเอง · Foley "3-way" ที่คลิปบอกว่า two-way ·
  "เข็มเล็กมาก (12G)" ซึ่ง 12G คือเข็มรูใหญ่ · misoprostol ที่เขียนหน่วยเป็นมิลลิกรัม
  ตอนนี้บันทึกไว้ใน `AGENTS.md` เป็นร้อยแก้ว ควรเป็น `{claim, sourceA, sourceB, verdict, evidence}`
  แล้ว lint ตรวจว่าไม่มีข้อไหนขัดกับ verdict
- **C4** ตรวจอัตโนมัติว่าคำที่โผล่ในเฉลยบ่อย ๆ ยังไม่มีใน glossary

## G. ทำไมการขึ้น prod ถึงช้า — วัดจริงจากรอบ 2026-09-22

Gate รอบแรกใช้ **~48 นาที แล้วแดงที่นาทีที่ 48** ทั้ง 48 นาทีจึงสูญเปล่า
นี่ไม่ใช่ความบังเอิญของรอบนี้ มันเป็นผลจากโครงสร้างของ `npm run gate` เอง

```
gate = build && lint:all && test:unit && playwright
```

| ขั้น | เวลา | ต้องใช้ dist ไหม |
|---|---|---|
| `build` (vite + prerender wiki/atlas/og) | **~23 นาที** | — |
| `lint:all` 44 ขั้นเรียงกัน | | **41 จาก 44 ไม่ต้องใช้** |
| `test:unit` 1,170 tests | | ไม่ต้องใช้ |
| `playwright` 748 tests × 4 browsers | | ต้องใช้ |

**ปัญหาเชิงโครงสร้าง 4 ข้อ**

1. **ของถูกและพังง่าย อยู่หลังของแพง** lint กับ unit test ไม่ต้องรอ build เลย
   มีแค่ `audit:contrast` ขั้นเดียวที่อ่าน `dist/` แต่ตอนนี้ต้องรอ build 23 นาทีก่อนเสมอ
   ถ้า lint ขั้นที่ 40 แดง ก็เสีย 25+ นาทีไปแล้วโดยไม่จำเป็น
2. **ตัวที่ flaky ที่สุดอยู่ท้ายสุด** Playwright เป็นขั้นที่แพ้การแย่งทรัพยากรง่ายที่สุด
   และมันรันเป็นขั้นสุดท้าย flake หนึ่งตัวจึงกินเวลาทั้ง run
3. **เรียงกันหมดทั้งที่ขนานได้** เครื่องมี 12 cores; build ใช้ core เดียวเป็นส่วนใหญ่
   `lint:all` กับ `test:unit` เป็นอิสระต่อกัน รันพร้อมกันได้
4. **prerender ทำใหม่ทุกครั้ง** โดยเฉพาะ OG cover ที่เป็นการ screenshot หน้า HTML จริง
   ทั้งที่ input ไม่ได้เปลี่ยน

**แนวทางแก้ เรียงตามผลต่อเวลา**

| | แก้อะไร | ได้อะไร |
|---|---|---|
| G1 | **สลับลำดับ**: `lint:all` (ยกเว้น audit:contrast) + `test:unit` → `build` → `audit:contrast` + `playwright` | รู้ผลพังใน ~5 นาทีแทน ~25 |
| G2 | **รัน lint:all กับ test:unit ขนานกัน** — เป็นอิสระต่อกัน | ตัดเวลาช่วงนั้นเกือบครึ่ง |
| G3 | **ข้าม prerender ถ้า input ไม่เปลี่ยน** (hash ของ input) โดยเฉพาะ OG screenshots | ตัดจาก build ได้มาก |
| G4 | ใช้ `@smoke` ระหว่างวนแก้ แล้วค่อยรันเต็มชุดครั้งเดียวก่อน push | |
| G5 | ย้าย gate ไป CI แบบ job ขนาน แล้วทำอย่างอื่นระหว่างรอ | **หมายเหตุ CI รันด้วย UTC** เทสที่ผูกกับวันต้องรันใต้ `TZ=UTC` ก่อน push |
| G6 | `regen:all` เป็นขั้นแรกของ gate เลย | ไม่เสีย run เพราะไฟล์ generated ค้าง |
| G7 | **ห้ามรันอะไรอย่างอื่นตอน gate** — dev server, agent, workflow | สาเหตุจริงของ 17 ตัวแดงรอบนี้ |

G1 + G2 + G7 ทำได้ทันทีโดยไม่แตะ logic อะไรเลย แค่เรียง `package.json` ใหม่

### G8 — gate ในเครื่องโหดกว่า CI จริง นี่คือสาเหตุหลักของการ "แดงแล้วต้องรันใหม่"

`playwright.config.js` ตั้งไว้ว่า

```js
workers: process.env.CI ? 2 : undefined   // ในเครื่อง = ครึ่งหนึ่งของ core = 6 บนเครื่อง 12 core
retries: process.env.CI ? 1 : 0           // ในเครื่อง = ไม่ retry เลย
```

แปลว่า `npm run gate` ในเครื่อง **รันหนักกว่าที่ CI จะรันจริง** คือ 6 workers ไม่มี retry
เทียบกับ CI ที่ 2 workers และ retry ได้ 1 ครั้ง ทั้งที่ comment ใน config เองก็เขียนไว้ว่า
engine ต้องการ "the machine to itself"

**หลักฐานจากรอบ 2026-09-22** รันเต็มชุดสองรอบที่ 6 workers ได้ 17 แดง แล้ว 16 แดง
โดยมีแค่ 7 ตัวที่ซ้ำกัน พอเอา 7 ตัวนั้นมารันแยกที่ 2 workers → **ผ่านหมด 64/64**
และ diff ของรอบนั้นไม่มีไฟล์ component / CSS / lib เลยสักไฟล์ มีแต่ data
จึงไม่มีกลไกใดที่เนื้อหาจะทำให้ปุ่ม "ไม่นิ่ง" ได้

**สิ่งที่ควรทำ**

- ก่อน push ให้รัน `CI=1 npx playwright test` **ไม่ใช่** `npx playwright test`
  เพื่อให้เงื่อนไขตรงกับ gate จริง ไม่งั้นจะไล่แก้ผีตลอด
- พิจารณาตั้ง `workers` ในเครื่องให้ต่ำลง (เช่น 4) แทน `undefined`
  เพราะ default ของ Playwright คือครึ่งหนึ่งของ core ซึ่งมากเกินไปสำหรับ suite ที่มี
  WebGL + PDF + service worker
- อาการที่ต้องอ่านให้ออก: **"element resolved … waiting for element to be visible, enabled
  and stable" แล้ว timeout** และ **"timeout while setting up page"** = เครื่องไม่พอ
  ไม่ใช่ของพัง ส่วนของพังจริงจะเป็น assertion ที่บอกค่าที่คาดกับค่าที่ได้
- ตัวชี้ขาดคือ **รันเฉพาะ spec ที่แดง แยก ที่ workers ต่ำ** ถ้าเขียวแปลว่าเป็นเรื่องทรัพยากร

## กฎเหล็กของงานกลุ่มนี้

1. **แก้ data + เพิ่ม guardrail — ไม่ใช่แก้ predicate**
   `isPastPaperQuestion` ถูก "แก้ให้หลวมขึ้น" มาแล้ว 2 ครั้ง และนับผิดทั้ง 2 ครั้ง
   ครั้งที่ 3 (รอบนี้) แก้ที่ data แล้วตัวเลขถูกทั้งสองทิศ
2. **วัดก่อนแก้** ทุกครั้ง — ตัวเลข blast radius คือตัวตัดสิน ไม่ใช่ความรู้สึก
3. **ถ้า lint สร้างปัญหาเอง ให้แก้ lint ไม่ใช่ไปรับมือปลายทาง**
   (`lint-academic-safety.mjs` ผลิตคำสะกดสั้นเอง จึงต้องแก้ที่ต้นทาง)
4. **อย่าเริ่มตอนใกล้สอบ** ทุกข้อแตะสิ่งที่นิสิตกำลังเปิดอ่าน
